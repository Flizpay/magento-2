FLIZpay for Magento 2

Accept FLIZpay payments through a hosted checkout and show available cashback in the Magento checkout.

About the extension

After a customer places an order, the extension redirects them to the secure FLIZpay payment page. Magento receives signed payment notifications, updates the order, creates the paid invoice, and records the final cashback.

Included

  • Guest and registered-customer checkout
  • Automatic webhook registration and verification
  • Cashback display and Magento total adjustment
  • Automatic paid invoice after successful payment
  • Cart restoration after failed or canceled payment
  • Privacy-safe operational logging

Requirements

  • Magento Open Source or Adobe Commerce 2.4.7–2.4.9
  • PHP 8.2–8.5, as supported by the Magento release
  • HTTPS storefront
  • EUR quote currency
  • Magento Luma or Blank checkout
  • Active FLIZpay merchant API key
Availability: FLIZpay appears at checkout only when it is enabled, the API key and connection are valid, the storefront uses HTTPS, and the quote currency is EUR.

Before installation

  • Back up the Magento files and database.
  • Confirm that Magento cron and production deployment are working.
  • Obtain the API key from the FLIZpay merchant dashboard.
  • Use a staging environment for the initial installation and payment test.

Installation and configuration

Install with Composer

To install from Packagist, run the following commands from the Magento root directory:

composer require flizpay/magento2
bin/magento module:enable FlizPay_Payment
bin/magento setup:upgrade
bin/magento setup:di:compile
bin/magento cache:flush

For production stores, complete the normal static-content deployment and production-mode process required by your Magento installation.

Configure FLIZpay

  1. In Admin, open Stores → Configuration → Sales → Payment Methods → FLIZpay.
  2. Set Enabled to Yes.
  3. Enter the API Key from the FLIZpay merchant dashboard.
  4. Click Save Config. The extension registers the secure webhook and verifies it with a signed test notification.
  5. Wait until Connection Status reports a successful connection, then flush the Magento configuration cache if necessary.
  6. Place a test order in your staging environment before enabling FLIZpay on the production storefront.

Payment behavior

Customer checkout

  1. The customer selects FLIZpay and places the Magento order.
  2. Magento creates the order with status pending_payment.
  3. The customer is redirected to the hosted FLIZpay payment page.
  4. After payment, the customer returns to Magento. A pending page waits briefly if the signed payment notification is still being processed.
  5. Magento trusts the signed webhook, not the browser return, to settle the order.

Payment results

FLIZpay resultMagento behavior
Pending / processingThe order remains pending_payment while Magento waits for a terminal result.
CompletedMagento records the capture, creates one paid invoice, and moves the order to processing.
Failed / canceledMagento cancels the order and restores the customer cart when the checkout session is available.

Cashback

The checkout can display the maximum available cashback percentage. This preview does not change the quote total. FLIZpay determines the actual cashback and sends the original and final amounts in the signed completed-payment notification.

Before settlement, Magento applies the difference as cashback across eligible products and shipping, including the proportional tax adjustment. The order and invoice then show the final paid totals.

Invoices and credit memos

  • A successful FLIZpay payment creates exactly one full paid invoice automatically.
  • For a completed payment, Magento permits one full offline credit memo.
  • An offline credit memo updates Magento records only. It does not send money through FLIZpay.
  • Refunds cannot currently be initiated through this extension or your FLIZ Business account. If a refund is required, repay the customer directly outside FLIZpay, for example by bank transfer. Then create the corresponding full offline credit memo in Magento Admin.
Not supported: partial or multiple invoices, partial credit memos, online refunds, merchant-initiated capture or void, Admin order payment, multi-address checkout, non-EUR checkout, Hyvä, PWA/headless, GraphQL checkout, and third-party checkout replacements.

Troubleshooting and maintenance

Troubleshooting

ProblemCheck
FLIZpay is missing at checkoutConfirm Enabled = Yes, EUR currency, HTTPS secure base URL, a saved API key, and a successful Connection Status.
Connection is not verifiedSave the API key again and confirm that the public HTTPS endpoint /flizpay/webhook is reachable through the firewall or proxy.
Order remains pendingCheck the FLIZpay payment state and var/log/flizpay.log. Do not manually mark the order paid based only on the browser return.
Customer cannot complete paymentConfirm the storefront session is active, retry from the restored cart when offered, and inspect the FLIZpay log for a safe error code.
Credit memo is rejectedCreate a full credit memo from the paid invoice and choose Refund Offline. Partial and online refunds are not supported.

Logging

Warnings and errors are written to var/log/flizpay.log. Enable Debug Logging temporarily for additional API and webhook diagnostics, then disable it again in production.

The dedicated log excludes API credentials, webhook signatures, customer data, and request or response bodies. Review a diagnostic copy before sharing it with support.

Update or disable

Update the Composer package using your normal controlled deployment, then run:

bin/magento setup:upgrade
bin/magento setup:di:compile
bin/magento cache:flush

To stop offering FLIZpay, set Enabled to No. Existing orders and payment records remain in Magento for operational and accounting history.
